## E2E runtime and flakiness

- **Parallel and sharded.** `tests/e2e/playwright.config.ts` sets `fullyParallel: true`;
  without it Playwright runs one file on one worker, and the whole suite lives in
  `smoke.spec.ts`, so CI ran 153 tests serially for about 10 minutes. The `e2e` job in
  `ci.yml` is a 3-way matrix (`--shard=N/3`, check names `Playwright (demo mode) N/3`,
  artifacts `playwright-results-N`), and each shard uses Playwright's default worker
  count. Tests share no state (each gets a fresh browser context and `page.goto('/')`),
  so the order does not matter.
- **Dev server only.** Many tests stub the IPC layer with
  `await import('/src/core/ipc.ts')` inside `page.evaluate`, which only resolves on the
  Vite dev server. Serving a production build (`vite preview`) breaks them, so do not
  switch the e2e web server to a build to save time.
- **Programmatic diff selections must sit inside row text.** `useStableSelection`
  (G47) ignores endpoints at layer level (`setStartBefore(row)`), so a test that builds a
  selection that way is not tracked and loses it on any re-render. Build it from text
  nodes inside `[data-diff-layer] > div` rows, the way a user drag ends. The copy-menu
  test failed about 9 times in 10 locally before this was fixed (2026-11-19).
- **Fixed: `a trackpad pan moves the long-line diff…`.** It runs at an 800 px viewport,
  where the toolbar overflows `#root`, and the `overflow: hidden` shell could still be
  scrolled. On the Linux runner the thumb drag shifted the whole app about 87 px, so the
  final track click landed off-screen. Fixed in the app with `overflow: clip` (G60), and
  covered by `the app shell never scrolls sideways when its toolbar is wider than the
  window` (2026-11-19).
- **Fixed: `dragging a diff selection past the right edge…`.** It read the pan offset
  while the edge-pan rAF loop was still running (pointer still past the edge), then moved
  the pointer back inside and expected no further movement, so any frame that ran between
  the read and the move failed it (119.5 vs 123 px; 2 of 5 local runs). It now moves back
  inside, waits two frames, then reads the offset and checks it holds (2026-11-20).
  General rule for gesture tests: take the baseline only after the gesture that should
  stop the motion, never while the motion is still running.
